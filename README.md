# 🎯 Purpose

**Dhiman Medicos is a pharmacy retail outlet management application.**

It is built for pharmacy owners, pharmacists, and retail-counter staff to manage:

- 💊 Medicine catalog and search
- 📦 Current stock and inventory
- 🧾 Supplier purchase invoices
- 🏷️ Batch numbers and expiry dates
- 💰 Internal net purchase rates
- 🛒 Retail sales and billing
- 📚 Sales/invoice history
- 🖨️ Printable invoices and PDF receipts
- 💬 Optional WhatsApp order communication

The public-facing medicine catalog is only one part of the system; the primary operational use case is **pharmacy retail management**.

# 🧾 Pharmacy Sales, Billing & Inventory

The application provides a pharmacy-facing sales, billing, inventory, and supplier-invoice workflow for retail pharmacy outlets.

### Invoice capabilities

- 🧾 Sales history with previous invoices
- 👁️ View existing invoices/receipts
- 🖨️ Print receipts using a print-safe invoice layout
- 📄 Save receipts as PDF through the browser print flow
- 📱 Print-friendly behavior on mobile and desktop
- 🧮 Retail invoices show the appropriate selling/billing values
- 🔒 Net purchase rate is internal pharmacy data and is **not exposed on retail invoices**

### Supplier invoice processing

Supplier invoice CSV files can be placed in `invoices/`. The GitHub Actions workflow processes them automatically.

The invoice processor can extract and maintain:

- Medicine name
- MRP
- Purchased quantity
- Batch number
- Expiry date
- Net purchase rate, when the supplier invoice provides the required rate/discount fields

The net purchase rate calculation currently uses the invoice's purchase/base rate and applicable discount:

```text
Net Purchase Rate = FTRATE − (FTRATE × DIS / 100)
```

If no discount is supplied, the base purchase rate is retained.

### Inventory batches

Batch-level inventory records preserve the batch number and expiry date so stock can be traced back to the supplier invoice.

### Duplicate purchase protection

Processed invoice files are tracked by content hash so rerunning the workflow does not accidentally add the same purchase stock twice.

# 🖨️ Invoice Printing

Invoices are designed to be separated from the normal application UI when printed.

The print workflow:

1. Opens a clean print document containing only the invoice.
2. Uses print-specific styling for paper-friendly output.
3. Supports browser printing to a physical printer.
4. Supports **Save as PDF** from the browser print dialog.
5. Keeps internal purchase/net purchase information out of the customer receipt.

For older invoices in Sales History, the receipt and PDF actions use the same print-safe invoice flow as newly generated invoices.

## Admin login

Set `NEXT_PUBLIC_SUPABASE_ANON_KEY` and `ADMIN_EMAILS` in Vercel. Create the approved admin user in Supabase Authentication (email/password). Admin staff sign in at `/admin/login`; `/pos`, `/inventory`, `/sales`, and their internal APIs are protected by the admin middleware.
